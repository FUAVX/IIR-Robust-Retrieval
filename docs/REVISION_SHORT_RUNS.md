# Revision with limited GPU time

No retraining is required for this revision. Preserve the historical source and
results, then add separately versioned checks and evaluations.

1. Publish the historical Colab training and Kaggle post-training source. Verify
   the five runtime SHA-256 values against `paper/ieee/data/models_manifest.json`.
2. Test diffusion on hand-computable graphs and compare iterative propagation
   with a linear-system solution. Compare dense and top-k query seeds on the
   existing epoch-100 descriptor cache. These are diagnostics, not test-set
   hyperparameter selection.
3. Run clean B0 epoch-12 evaluation with fixed settings and FP32 inference on a
   Kaggle T4, if available. Save descriptors for CPU search experiments. Use a
   separate notebook and strict runtime limit; do not launch the historical full
   coordinator or retrain.
4. Inventory raw historical outputs, publish a checksummed download, and verify
   its availability before replacing the pending raw-output URL.
5. Update the paper after the checks. Keep epoch-100 results as historical
   evidence; put sensitivity in the supplement and consolidate limitations.

ROxford/RParis inference and additional corruption/geometry runs are follow-up
work, conditional on available time. Do not describe them as completed. R1's
validation-selected epoch-27 weights are absent from the supplied archive.

## CPU setup

Create an isolated environment and install
`artifacts/revision-validation/requirements-cpu.txt`. Historical training
verification additionally needs a compatible `torch`/`torchvision` pair.
Use the existing `kaggle-account` bridge for authenticated commands. Do not run
older publishing utilities that authenticate outside that bridge.
